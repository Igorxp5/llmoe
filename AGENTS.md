# LLMOE Project Reference

Implementing OLMoE-1B-7B inference engine in C — leveraging IREE for tokenization and runtime components.

## Build system

### Compiler & flags
- **Compiler**: `gcc`, C11
- **Static linking**: `-static`. Object files MUST come before `$(IREE_LIBS)` on the link line.
- **CFLAGS must include**: `-DIREE_ALLOCATOR_SYSTEM_CTL=iree_allocator_libc_ctl`
- **Include paths**: `-Ivendor/iree/runtime/src -Ivendor/iree/third_party/flatcc/include -I. -Isrc`
- **Separate flags from libs**: `$(LDFLAGS)` = linker flags only. `$(LDLIBS)` = libraries, placed after objects.

### IREE
- Vendored at `vendor/iree/`, CMake-built once to `build/iree-install/` (stamped by `$(IREE_STAMP)`)
- All `.a` libraries wrapped in `-Wl,--start-group ... -Wl,--end-group` to resolve circular deps
- Only tokenizer + base + flatcc libraries are linked; HAL/VM/ukernel excluded to avoid arch conflicts

### Source discovery
- Use `$(shell find src -name '*.c')` — project has subdirectories (e.g. `src/olmoe/`)
- Tests use `$(wildcard tests/*.c)`

### Test runner link
- Must link project `.o` files — not just `tests/*.c` — but **exclude `build/src/main.o`** to avoid duplicate `main`
- Must depend on `prepare` to create output directories

### VSCode (`.vscode/c_cpp_properties.json`)
- Include paths: add `${workspaceFolder}/vendor/iree/runtime/src` and `${workspaceFolder}/vendor/iree/third_party/flatcc/include`
- Defines: add `IREE_ALLOCATOR_SYSTEM_CTL=iree_allocator_libc_ctl`

## Python scripts

- Always use `.venv/bin/python` or `.venv/bin/pip`
- All scripts live in `scripts/`. **Never** inline generation logic in the Makefile.
- Generated `.inc` files must start with:
  ```c
  // Auto-generated by scripts/<script>.py
  // Source: <sys.argv[1]>
  // DO NOT EDIT BY HAND
  ```
  Use `sys.argv[1]` for the source path — never a hardcoded string.

## Tokenizer (`src/olmoe/`)

### Implementation (`tokenizer.c`)
- **No runtime file I/O**: do not read `tokenizer.json` on disk. Embed it as `static const uint8_t[]` in a generated `.inc` file.
- At init, call `iree_tokenizer_from_huggingface_json()` with the embedded data. IREE auto-detects NFC + ByteLevel + BPE — individual component APIs are not needed.
- **Lazy-init** on first call (static variable).
- **Interface**: `void olmoe_tokenize(uint8_t* in, uint16_t* out)`. Output is terminated with sentinel `0xFFFF` (vocab is ~50K, so this is unambiguous).
- Encode with `IREE_TOKENIZER_ENCODE_FLAG_NONE` (no special tokens — matches the Python oracle default).
- Fixed output buffer of 1024 tokens.

### Oracle (`scripts/tokenize_cli.py`)
- Used **only** for generating expected test outputs. **Never** used at runtime by C code.
- Run: `.venv/bin/python scripts/tokenize_cli.py models/OLMoE-1B-7B-0924-Instruct/tokenizer.json tokenize "<text>"`

### Data generation (`scripts/generate_tokenizer_data.py`)
- Reads `tokenizer.json`, writes `src/olmoe/tokenizer_data.inc`
- Auto-triggered by Makefile when the JSON or script changes

## Testing

- **Framework**: `tests/assertion.h` defines `ASSERT(c)` — returns `1` if condition is true (failure). Test functions return `0` on success.
- Test files go in `tests/`, auto-discovered by `$(wildcard tests/*.c)`
- **Oracle tests**: expected token IDs are hardcoded from the Python oracle — not computed at test time.
